# 麒麟 aarch64 安装说明

安装包：**`KnowledgeBase_1.65.0_arm64.deb`**（54 MB）

已验证的包信息：

```
Package:        knowledge-base
Version:        1.65.0
Architecture:   arm64        ← 与麒麟 / 飞腾 / 鲲鹏完全匹配
Installed-Size: 79 MB
Depends:        libc6, libwebkit2gtk-4.1-0, libgtk-3-0,
                libayatana-appindicator3-1, librsvg2-2, fonts-noto-cjk
```

---

## ⚠️ 安装前必读：唯一的硬障碍

**`libwebkit2gtk-4.1-0` 是 Tauri 2 的硬依赖，缺它应用无法启动。**
而麒麟 V10 SP1/SP2 官方源通常只有 4.0，没有 4.1。

**你的麒麟机必须先满足这一条**，否则 `apt install` 会直接报依赖缺失。

先检查：

```bash
dpkg -l | grep webkit2gtk-4.1
# 或
pkg-config --modversion webkit2gtk-4.1
```

若有输出 → 直接跳到「安装步骤」。

若报缺失，三个办法（任选其一）：

| 方案 | 说明 |
|---|---|
| **A. 升级到 V10 SP3**（推荐） | SP3 基线较新，自带 4.1 的概率最高。最省事 |
| **B. 从麒麟开发者社区取包** | 拿到 `libwebkit2gtk-4.1-0_*_aarch64.deb`，连同依赖一起摆渡过去 |
| **C. 内部软件源** | 若单位有内网 apt 源，让管理员加上 4.1 的包 |

> 建议动身前先跟 IT 部门确认 4.1 的来源，这是成败关键。

## 方式一：先在联网麒麟机上收集依赖（推荐）

如果你有**另一台同版本联网的麒麟机**（`lsb_release -a` 必须完全一致），在它上面跑：

```bash
# 把 deb 包拷过去，然后：
bash scripts/collect-offline-deps.sh --deb ~/Downloads/KnowledgeBase_1.65.0_arm64.deb
```

脚本会自动完成：

- 校验架构必须是 aarch64
- 探测 `libwebkit2gtk-4.1` 能否获取，缺失时给出镜像参考
- 用 `apt-get --download-only` 拉齐主包 + 全部依赖
- 生成 `Packages.gz` 本地源索引
- 输出 `README-离线安装.txt` 安装指引

产物是一个 `kb-offline-repo/` 目录，**整个拷到 U 盘，摆渡到离线麒麟机**即可。

---

## 方式二：直接在离线麒麟机上装（依赖已备齐）

把 deb 和所有依赖 deb 放进同一目录（如 `~/kb-offline/`）：

```bash
cd ~/kb-offline

# 方案 A：建本地源（推荐，依赖进 apt 数据库，便于后续升级）
sudo dpkg-scanpackages . /dev/null 2>/dev/null | gzip > Packages.gz
sudo mkdir -p /var/local/kb-repo
sudo cp *.deb Packages.gz /var/local/kb-repo/
echo 'deb [trusted=yes] file:///var/local/kb-repo ./' | \
  sudo tee /etc/apt/sources.list.d/kb-offline.list
sudo apt-get update

sudo apt-get install -f
sudo apt install ./KnowledgeBase_1.65.0_arm64.deb
```

```bash
# 方案 B：不建源，直接批量安装
sudo dpkg -i *.deb
sudo apt-get install -f        # 依赖已离线备齐，这步不会联网
```

## 两个必须知道的限制

### 1. 自动更新不可用

Tauri 的 updater 在 Linux 上**只支持 AppImage，不支持 deb**（框架限制）。
所以应用内「检查更新」不会有新版本提示 —— 这是预期行为，不是装错了。

**升级方式**：拿到新版本 deb 后

```bash
sudo apt install ./KnowledgeBase_<新版本>_arm64.deb    # 版本更高则自动替换升级
```

### 2. kysec 安全模块可能拦截

麒麟默认启用 kysec，会拦截非商店来源的应用安装：

- 双击 deb 被拒 → 「设置 → 安全 → 应用安装」放开非商店来源
- 启动被拦 → 查 `/var/log/kysec*`，需 IT 放行
- 调试期可临时 `sudo kysecctl --disable`，**生产环境不要关闭**

## 排查入口

| 位置 | 内容 |
|---|---|
| `~/.local/share/com.agilefr.kb/logs/` | 应用运行日志（tauri-plugin-log） |
| `<数据目录>/crash/crash-YYYYMMDD.log` | 崩溃报告 |

启动异常时先看这两处，比猜要快。

## 后续版本升级流程

```
联网 Windows 机：git push tag（或 gh api 打标签）
        ↓
GitHub Actions 自动构建 arm64 deb（约 10 分钟）
        ↓
下载 deb + 更新离线依赖包
        ↓
U 盘摆渡到麒麟机
        ↓
sudo apt install ./KnowledgeBase_<新版本>_arm64.deb
```

依赖包只在**首次**需要完整收集；后续升级若未引入新依赖，只带主包即可。
