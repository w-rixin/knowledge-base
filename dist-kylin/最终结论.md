## 为什么装不上（硬性技术原因）

Ubuntu 全部版本的 `libwebkit2gtk-4.1-0` 依赖声明都是：

```
libc6 (>= 2.35)
```

而你的 glibc 是 **2.31**。差 4 个小版本，**apt/dpkg 会直接拒绝安装**，无法用 `--force-depends` 安全绕过
（webkit2gtk 调用了大量 2.32+ 才有的符号，强行装上会在启动时符号解析失败）。

而 webkit2gtk-4.1 **只存在于 Ubuntu 22.04（jammy）及以后**，
Ubuntu 20.04（focal，即你的麒麟基线）官方源里只有 4.0。

这是一个**闭环困境**：

```
麒麟基线 = Ubuntu 20.04  →  源里只有 webkit 4.0
Tauri 2   = 必须 webkit 4.1
webkit 4.1 = 只在 Ubuntu 22.04+  →  要求 glibc 2.35
你的 glibc = 2.31        →  装不了 22.04 的包
```

> 同类案例：Clash Verge Rev（也是 Tauri 2 应用）在 Mint 20.3（glibc 2.31）上的
> 结论同样是「装不上，只能源码编译或退 Tauri 1.x」。

## 三条可行路径

### 方案 A：升级麒麟系统（最推荐）

**升到 V10 SP3**——官方白皮书显示 SP3 的 glibc 基线更新，自带 webkit2gtk-4.1 的概率最高。

```bash
# 先确认当前是否已是 SP3
cat /etc/kylin-build        # 你的是 Kylin-Desktop-V10-GFB，需问 IT 有无 SP3 镜像
```

优点：一次解决所有兼容问题，后续升级也不用再折腾。
缺点：需要 IT 支持，有升级窗口期。

**找 IT 时可以直接说**：「需要 V10 SP3 或更新的桌面版系统，因为要部署基于 Tauri 2 的应用，
它硬依赖 webkit2gtk-4.1，当前 V10 GFB 版本的 glibc 2.31 无法满足」。

---

### 方案 B：从源码编译 webkit2gtk-4.1

理论上可行，但成本很高：

- webkit2gtk 是超大 C++ 项目，编译需**数十GB 磁盘、数小时编译**
- 依赖 GTK3 开发库、gstreamer、libicu70、libsoup3 等一长串
- **libicu70 与麒麟自带的 libicu 版本冲突**，需额外处理
- 编译完还要处理 so 版本号、Tauri 的 `libwebkit2gtk-4.1.so.0` 链接问题

除非你愿意投入大量时间，**不建议**。

---

### 方案 C：改用 Tauri 1.x 版本（改变技术路线）

如果应用不急着上，本项目的代码本身做过移动端适配，
理论上可以回退到 Tauri 1.x 重新构建——Tauri 1.x 依赖 **webkit2gtk-4.0**，
而你的系统**正好有 4.0**。

代价：Tauri 1.x 与 2.x 的 Rust API 差异较大，需要改代码；
部分插件（updater、global-shortcut 等）在 1.x 上版本也不同。

**但这是一条确定能走通的路。**如果麒麟系统无法升级，这是唯一可靠选择。

---

## 我的建议

**优先推动方案 A（系统升级）。**理由：

1. 你现在缺的不只是一个包，而是**整条生态链**——AI 相关的库、各种新工具，
   未来都会撞上glibc 2.31 的天花板
2. 升级一次，长期受益
3. 方案 B/C 都是在绕过问题，且成本都不低

如果 IT 明确说不能升级，再走方案 C（Tauri 1.x）——我可以帮你评估改造工作量。
