# 麒麟安装失败分析与解决方案

## 报错原文

```
KnowledgeBase 依赖关系不满足 libayatana-appindicator3-1, libwebkit2gtk-4.1-0
```

---

## 核心判断：两个依赖性质完全不同

| 依赖 | 性质 | 能否解决 |
|---|---|---|
| `libayatana-appindicator3-1` | **托盘图标库**，缺失只影响右下角托盘图标 | 可移除该依赖 |
| `libwebkit2gtk-4.1-0` | **WebView 引擎**，Tauri 应用的命脉 | **无法移除，必须解决** |

`libwebkit2gtk-4.1` 是硬需求——Tauri 2 的界面完全靠它渲染，没有它应用根本起不来。
所以只要解决它，应用就能跑。

---

## 为什么麒麟源里没有 libayatana-appindicator3-1

麒麟 V10 软件源采用「安全白名单制」，仅同步通过国密认证的组件。
`ayatana-indicators` 系列因未通过适配测试被主动剔除。

而 Ubuntu 22.04 已把 `libappindicator3-1` 重构为 `libayatana-appindicator3-1`，
Tauri 2 跟随新版命名，声明依赖的是 `libayatana-appindicator3-1`，
麒麟源里恰好没有这个命名。

---

## 方案一：移除托盘依赖（推荐先试）

**思路**：托盘图标不是核心功能，移除该依赖后应用能正常启动，
只是右下角没有图标。窗口、编辑、搜索、图谱全部不受影响。

需要改 deb 内部的 control 文件，重新打包。

### 操作步骤（在联网机上做，不需要麒麟参与）

```bash
# 1. 解包
mkdir -p /tmp/kb-fix && cd /tmp/kb-fix
ar x KnowledgeBase_1.65.0_arm64.deb

# 2. 解出 control
tar -xzf control.tar.gz
nano control            # 或 gedit

# 3. 删除这一项（保留其它依赖）：
#    libayatana-appindicator3-1

# 4. 重新打包 control
tar -czf control.tar.gz ./control

# 5. 重新打包 deb
ar rcs KnowledgeBase_1.65.0_arm64-nodeps.deb \
   debian-binary control.tar.gz data.tar.gz
```

但这样仍需解决 `libwebkit2gtk-4.1-0`，否则还是装不上。

---

## 方案二：解决 libwebkit2gtk-4.1（真正的关键）

### 先查源里到底有没有

在麒麟机上执行（**仅查询，不安装**）：

```bash
apt-cache policy libwebkit2gtk-4.1-0
apt-cache search --names-only 'webkit2gtk-4'
apt-cache search webkit2gtk | head -20
```

**三种可能结果**：

| 输出 | 含义 | 下一步 |
|---|---|---|
| 有 `Candidate: x.x.x` | 源里有，只是没装 | 直接 `sudo apt install libwebkit2gtk-4.1-0` 即可 |
| `N: Unable to locate` | 源里没有 | 需要外部取包（见下） |
| 只列 4.0 | 只有老版本 | 必须外部取包 |

> 很多麒麟 SP3 其实已经带 4.1，只是未预装。先查再下结论。

### 若源里有 —— 最简单

```bash
sudo apt update
sudo apt install libwebkit2gtk-4.1-0 libayatana-appindicator3-1
sudo apt install ./KnowledgeBase_1.65.0_arm64.deb
```

### 若源里没有 —— 三个获取途径

#### 途径 A：从 Ubuntu 22.04 取包（最可行）

webkit2gtk-4.1 在 Ubuntu 22.04 源里是标准包，aarch64 架构齐全。
麒麟 V10 基于 Ubuntu 20.04，但 **glibc 通常兼容**（22.04 需 glibc 2.35，V10 SP3 接近此值）。

在**联网机**上：

```bash
# 加 Ubuntu 22.04 源（临时，仅用于下载，不覆盖麒麟源）
sudo add-apt-repository "deb [arch=arm64 trusted=yes] http://ports.ubuntu.com/ubuntu-ports jammy main universe"

# 只下载不安装
mkdir -p ~/kb-deps && cd ~/kb-deps
sudo apt-get update
sudo apt-get download libwebkit2gtk-4.1-0 \
  libjavascriptcoregtk-4.1-0 libsoup-3.0-0 \
  libwebkit2gtk-4.1-common libflite1 libavif16 \
  libharfbuzz-icu0 libicu70 libenchant-2-2 libsecret-1-0

# 把整个 kb-deps 目录拷到 U 盘，摆渡到麒麟机
```

麒麟机上安装：

```bash
cd ~/kb-deps
sudo dpkg -i *.deb          # 顺序可能报错
sudo apt-get install -f    # 自动补齐剩余依赖
```

> ⚠️ 注意：`libicu70` 在麒麟上可能已有 `libicu67`/`libicu72`，
> 版本冲突时跳过该包，让 `apt-get install -f` 用麒麟自己的版本顶上。

#### 途径 B：麒麟官方 SP3 源

```bash
# 麒麟 SP3 源（若你是 SP1/SP2，可尝试直接用 SP3 的包）
echo "deb [arch=arm64] http://archive.kylinos.cn/kylin/kylinsourcev10 sp3 main" | \
  sudo tee /etc/apt/sources.list.d/kylin-sp3.list
sudo apt update
apt-cache policy libwebkit2gtk-4.1-0    # 看有没有
```

⚠️ 混用不同 SP 版本的源有风险，**仅在途径 A 失败时尝试**。

#### 途径 C：升级到 SP3（最彻底）

SP3 基线较新，自带 4.1 的概率最高。需 IT 支持。

---

## 途径 A 的完整操作脚本

如果你有**联网的 x86 Linux 机器**（Ubuntu 22.04 即可），我已准备好脚本：

```bash
# 在联网机上（不一定是 aarch64，因为只下载不运行）
bash fetch-webkit-deps.sh
# 会生成 kb-deps/ 目录，拷到U盘摆渡到麒麟机
```

---

## 完整安装流程（依赖齐全后）

```bash
# 1. 装依赖
sudo apt install ./kb-deps/*.deb || sudo dpkg -i kb-deps/*.deb && sudo apt-get install -f

# 2. 装应用
sudo apt install ./KnowledgeBase_1.65.0_arm64.deb

# 3. 验证
dpkg -l | grep knowledge-base      # 应显示 ii
KnowledgeBase                      # 应打开窗口
```

---

## 优先级建议

1. **先查源里有没有 4.1** —— 可能根本不需要外部取包
2. 有 → 直接装，5 分钟搞定
3. 没有 → 走途径 A（Ubuntu 22.04 取包）
4. 途径 A 也失败 → 找 IT 谈 SP3 升级

---

## 托盘图标怎么办

如果 `libayatana-appindicator3-1` 始终装不上：

- **不影响使用**：应用窗口、编辑、搜索、图谱、导出全部正常
- **只是没有右下角托盘图标**
- 需要托盘图标时，可从 Ubuntu 22.04 单独取该包（体积很小，24KB）
