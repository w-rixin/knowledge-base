### 核心结论

Rust 代码层改造量 ≈ 0。项目已为跨平台而写，关键依据：
- `Cargo.toml:119` 桌面依赖已用 `cfg(any(windows, macos, linux))` 分组

- `lib.rs:930` 已写好 `#[cfg(target_os="linux")] libpdfium.so` 路径
- `ocr.rs:58` 已写好 `#[cfg(unix)]` 自动 chmod +x
- `converter.rs:160` 非 Windows 走 `soffice`
- `capabilities/default.json` 的 platforms 已含 linux
- `resources` glob `resources/ocr/RapidOCR-json*` 已能同时匹配 .exe 与无扩展名 Linux 版

### 真正障碍（3 个）

1. **webkit2gtk-4.1 缺失**（环境层最硬）：Tauri 2 硬依赖 4.1，麒麟 V10 SP1/SP2 源里只有 4.0。

2. **RapidOCR-json.exe**（16MB Windows PE）：需 Linux aarch64 版，官方 Release 多为 x64，可能需自行 PyInstaller。
3. **pdfium.dll**（7MB Windows DLL）：PDFium 无官方 Linux 预编译，需从源码（gn/ninja）编译。

**重要：后两者缺失时均优雅降级**，不阻断启动：
- pdfium 缺失 → `lib.rs:939` 仅 log::warn，PDF 退回 pdf-extract 主路径
- OCR 缺失 → `ocr.rs:214` is_available() 检查文件存在性，功能自动关闭
→ 策略：可先出「无 OCR 的可用版本」，降低首版风险。

### 关键技术决策：为何用平台专属配置文件而非 targets 数组

tauri-bundler 对 deb/rpm/dmg 有 cfg 门控（跨平台自动跳过），但 **nsis 被刻意不 cfg 门控**
（为支持 Linux/mac 上用 cargo-xwin 交叉打 Windows 包）。
若把 `["nsis","deb"]` 写在同一数组，在麒麟上执行 tauri build 会尝试交叉构建 Windows 安装包。
故采用 tauri.linux.conf.json 覆盖，合并语义为 RFC 7386 JSON Merge Patch（对象递归合并、数组整体替换）。
注意 `linux.deb.depends` 是**追加**而非替换 tauri-bundler 自动计算的依赖。

### 遗留风险

1. webkit2gtk-4.1 无官方麒麟源，属外部依赖，需与 IT 部门确认可获得性
2. OCR 引擎 aarch64 包未必现成
3. PDFium 需源码编译，C++ 工具链有成本
4. 麒麟 kysec 安全模块可能拦截 .deb 内 sidecar 启动，需 IT 放行
5. fonts-noto-cjk 包名在部分麒麟版本不同
6. 建议优先麒麟 aarch64 原生构建，不从 Windows 交叉编译（glibc + webkit 链接会反复阻塞）

### 🔴 重要技术发现：Tauri updater 在 Linux 上不支持 deb

官方行为：`createUpdaterArtifacts` 在 Linux 上只从 **AppImage** 生成
`.AppImage.tar.gz` + `.sig`（v1Compatible 模式），**deb 不生成 updater 产物**。
故麒麟装 deb 后应用内「检查更新」不会有提示 —— 框架限制，非配置错误。

应对：麒麟场景建议 deb + 人工升级（`apt install ./新版本.deb` 自动替换同包）。
改 AppImage 可启用自动更新，但 **kysec 会拦 FUSE 挂载**（需 `kysecctl --disable`
或 `APPIMAGE_EXTRACT_AND_RUN=1`），且麒麟生态以 deb 为主，得不偿失。

注：`plugins.updater` 配置与 pubkey 三平台共用，无需改动；Win/macOS 自动更新不受影响。

### 离线场景的两个固有限制

1. 自动更新不可用（见上）
2. AI 功能（MCP sidecar / AI 问答 / 网页剪藏）需网络，**但核心本地功能
   （笔记/搜索/图谱/导出）完全不受影响** —— 项目定位本地知识库，离线可用性良好

### 遗留风险（同第一轮，仍未解决）

1. webkit2gtk-4.1 无官方麒麟源 → 离线机必须提前备齐该包，是离线部署的头号难点
2. OCR 引擎 aarch64 包未必现成（官方 Release 多为 x64）
3. PDFium 需源码编译（gn/ninja）
4. kysec 可能拦截 .deb 内 sidecar（kb-mcp）启动，需 IT 放行
5. fonts-noto-cjk / libayatana-appindicator3-1 包名在部分麒麟版本不同
